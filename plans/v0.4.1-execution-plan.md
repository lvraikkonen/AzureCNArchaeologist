## 实现变更

### 1. SLA route map 平价

- 修改 `SourceContentProjector` 的 runtime definition 构建：对 `SupportArticlePage` 按 language 调用现有 `build_support_url_route_map()`，并复制嵌套 `extraction` 字典，避免修改 `ProductManager` 缓存。
- 当前页和历史版本使用同一份 Product Definition route map；历史版本仅覆盖 slug。
- 不复制产品专用映射，不改变非 SupportArticle 投影、Business Payload 或证据 Schema。

### 2. 稳定异常分类

- 仅将 `FlexibleBuilder.build_complex_content_groups()` 中“占位节点”及“无可见状态内容”两个分支改为：

  ```python
  SourceReachabilityError("missing_cms_state_content", ...)
  ```

- Sidecar 使用稳定 code 和 `source_reachability` 阶段；Batch manifest/report 仍记录 pipeline 的 `extract` 阶段。
- 其他 `ValueError` 保持原分类；不增加产品名分支、不生成空内容、不降级为 warning。

### 3. 日志收敛

- 删除休眠的 `setup_logging()`、只被它使用的根目录文件 sink settings 及 `src.core` 导出；保留 `get_logger()` 和现有轻量工具。
- 不删除用户本地已存在且 ignored 的 `logs/` 文件，只确保代码不再创建或写入它们。
- `pipeline-run`、`pipeline-resume`、`pipeline-validate` 在命令作用域内静默 `src`/`scripts` 的逐项 loguru 输出，并在结束时恢复 logger 状态。
- 为 `PipelineCoordinator` 增加可选的聚合进度回调，CLI 每阶段最多约每 10% 输出一次，不显示 item 级操作细节。
- CLI 结束时输出总计、按 stage/code 聚合的失败摘要，以及 manifest、report、review queue、JSONL 和 run 目录路径；退出码不变。
- JSONL 的失败 item 事件增加 `message`、`diagnostic_path`；preflight/validation 分别补 `parseability_path`/`validation_path`。成功事件保持精简，生命周期和 Payload 不受影响。

### 4. 语义规范化与文档

- 只为 `html_fragment_model()`、`semantic_model()`、`semantic_fingerprint()`、`diff_document()` 补测试，锁定当前算法。
- 覆盖空白、entity、NFC、注释忽略、正文/价格、节点顺序、重复节点、`href`/`src`/关键属性，以及稳定 diff 路径和 `MAX_DIFFS=20`。
- 若测试暴露真实算法缺陷，先停止并记录影响范围；未经另行确认不在 v0.4.1 顺带修改算法。
- 重写 README：当前目标、四种策略、目录与 CLI、单项与正式 Batch 区别、安全 Review→Release→upload 流程、Frozen HTML/`soft-category.json`、策略重放保证边界、产物用途、诊断方法及 clean-worktree 操作纪律。
