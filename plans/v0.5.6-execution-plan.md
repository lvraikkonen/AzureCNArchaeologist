## 3. 生产 Filter-control truth contract

本节应以 add-only `docs/adr/0092-filter-control-truth-reconciliation.md` 冻结。ADR-0090 的 desktop-default authority 保持原义；ADR-0092 只增加 owner、bounded responsive reconciliation 和 canonical consumer 规则。

### 3.1 F1：unique outermost formal selector owner

给定页面内所有 `div.technical-azure-selector.pricing-detail-tab` candidates：

1. 对每个 candidate 判断其是否被另一个 candidate 严格包含；
2. outermost set 只含不被其他 candidate 包含的 candidates；
3. 只有 outermost set 恰好一个时，才把它作为 filter owner；
4. zero 或 multiple outermost candidates 继续 `ambiguous_filter_root`；
5. nested descendants 仍属于 owner 内容，不从 DOM 删除、不改 Source bytes；
6. 不按 document position、DOM depth、size、option count、active class、title/text 或 product key 决胜。

该规则在 current scan 中只改变已失败 items，不得改变任何 current succeeded payload。它让双语 PostgreSQL 进入下一步，并让 mysql/purview/storage-files 得到更精确 error attribution。

### 3.2 F2：bounded exact unselected mobile duplicate suppression

只在以下 predicates 全部成立时，canonical mobile control 可以保留一条、抑制额外 duplicate：

1. F1 已证明唯一 owner；
2. duplicates 的 closed semantic tuple exact equivalent；tuple 只含第 3.2.1 节的命名字段；
3. 被抑制 rows 全部 unselected/non-default；
4. owner 恰有一个 direct material `div.tab-content` state-content root；
5. 抑制后 mobile href/value 唯一，desktop/mobile domain 精确一一对应；
6. desktop default 自身唯一，并继续满足 ADR-0090；
7. 每个 canonical target 在 owner 内唯一、可达且有 material state content；
8. 生成 finding code `suppressed_exact_mobile_filter_option_duplicate`，evidence 至少包含 filter key、semantic tuple、retained index、suppressed indexes 和 owner/content-root facts。

该 finding 不加入 frozen Finding Policy 1.0，依照 `unknown_code_disposition=fail_closed` 保持 approval-blocking。计划不为提高 eligibility 建立 policy successor。

规则只应修复 `zh-cn/postgresql`。`zh-cn/cache` 缺可信 state body，`zh-cn/mysql` 有 earlier parser/preflight blocker；selected、non-exact、跨 target、跨 label 或 multiple-root duplicate 必须失败。

#### 3.2.1 F2 closed semantic tuple

ADR-0092、production tests 与 independent tests 必须共同冻结以下 allowlist；括号内是当前 canonical/source row 对应语义：

1. `filter_key`：所属 `ReachabilityFilterDefinition.filter_key`；
2. `normalized_local_target`：由 Source `data-href` 规范化得到的 local fragment，对应 canonical `ReachabilityOption.href`；
3. `normalized_raw_machine_value`：Source `value` 经现有 attribute trim/normalization 后、在任何 region target canonicalization 之前的 machine value；
4. `normalized_label`：经现有 text normalization 得到的 label，对应 canonical `ReachabilityOption.label`；
5. `source_selected_marker`：Source option 是否物理声明 `selected`；
6. `canonical_is_default`：按 desktop-authoritative default truth 得到的 `ReachabilityOption.is_default`；
7. `parent_value`：canonical hierarchical owner value；当前 PostgreSQL region rows 必须为 `null`；
8. `parent_panel_id`：canonical hierarchical owner panel ID；当前 PostgreSQL region rows 必须为 `null`。

`parent_value` / `parent_panel_id` 被明确列入，是因为它们会改变 hierarchical state ownership；不是动态扩展入口。禁止 whole-node equality、whole-attribute-map equality、serialized DOM equality、SHA/hash-based duplicate identity，或运行时追加 tuple 字段。Source DOM 不删除、不重写；suppression 只发生在 canonical projection 中。

### 3.3 F3：singleton responsive target triangulation

当 mobile href 与 raw value 不一致时，现有“href 总是 authoritative”不能覆盖所有 Source signatures。只有以下事实同时成立，才能把 mobile canonical href 重建为 desktop target：

1. region domain 在 mobile 和 desktop 各恰好一个 option；
2. desktop href 是合法 local fragment，owner 内 target 恰好一个；
3. mobile raw value 精确等于 desktop target identity；
4. desktop/mobile label 精确相同；
5. desktop default 唯一，页面 default summary 与其一致；
6. mobile selected/default 不引入第二 identity；
7. 唯一矛盾是 mobile `data-href`；
8. 保留 approval-blocking finding code `filter_machine_value_target_drift`，message/evidence 必须说明本次 canonical direction 由 singleton triangulation 证明，不能谎称错误 mobile href authoritative。

规则只应修复双语 `hpc-cache`。多 option、multiple/missing desktop default、summary conflict、label mismatch、target missing/duplicate、owner 外 target 都失败；`en-us/managed-grafana` 是强制反例。

### 3.4 F4：RegionFilter 必须消费 canonical SourceReachability

1. `ExtractionCoordinator` 在 strategy selection/execution 前仍只解析一次 canonical `SourceReachability`；
2. `RegionFilterStrategy` constructor/execute contract 接收 mandatory result，与 `ComplexContentStrategy` 同样 fail-closed；
3. 用窄 adapter 将 canonical region definitions、options、labels、default 和 ordered states 投影到当前 RegionFilter builder 所需的数据；
4. 不重新调用 legacy `FilterDetector` 决定 region domain/default/target；
5. 必要的 hidden software metadata 与 `RegionProcessor` content extraction 可以暂时保留，但不得覆盖 canonical region truth；
6. optional `None`、try/except fallback、feature flag、product allowlist 或 dual-read “择优”均禁止；
7. 双语 `app-configuration` 应依 ADR-0090 得到 3 states 且无新 finding；mobile selected marker conflict 不重新升级为 error；
8. 所有 current passing RegionFilter items 在 frozen inputs 下完整 Business Payload exact bytes。

如果最小 bridge 无法保持 payload bytes，停止并展示具体 consumer/API gap；不得在 v0.5.6 顺带重写 RegionProcessor 或 Flexible builder。

### 3.5 Error and finding behavior

- F1 无唯一 owner：`ambiguous_filter_root`；
- F2 predicate 任一不满足：保持原 duplicate/domain/content error，不抑制；
- F3 predicate 任一不满足：保持原 responsive mismatch/error；
- canonical reachability 与 strategy contract/binding 不一致：structured fail-closed error，不抛裸 `ValueError`；
- finding 必须进入 diagnostics/validation/review projection，不进入 Business Payload；
- validation passed、L3b passed 与 approval eligible 分开统计。
