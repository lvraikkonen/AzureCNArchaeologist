# Audit Source HTML Structure Without Repairing Input

v0.4 runs a deterministic, read-only Source HTML Structure Audit after input parseability and before extraction, emitting exact source/line/DOM evidence and conservative upstream edit suggestions for high-confidence wrapper, section-boundary, or emitted-fragment identity defects. The audit never rewrites canonical bytes, applies a candidate patch in memory, changes Product Definition or baseline identities, or substitutes product-specific extraction exceptions; a safe suggestion may be generated only when parser agreement, visible text, tables, scripts, controls, targets, and reachability identities remain unchanged. A defect that still permits a faithful contract-valid Payload remains advisory, while a defect that would require source repair or an ownership guess is a Blocking Source Structure Finding and fails before Payload generation.

P2 projects these findings into each item's schema-validated Validation Projection. A deterministic, version-controlled planning inventory may summarize findings directly from pinned canonical sources for upstream coordination, but it is not a Batch Run report or a disposition authority. The batch-level Upstream Verification Report remains part of Report 2.0 in P4.
