# 增量变化与未结束 Batch 边界

## 背景

上游不仅会同时更新中英文 HTML，也可能更新可信 `soft-category.json`；参考 Product Definition 的源路径、页面类型或 Strategy 也可能变化。另一方面，增量 Batch 可能在抽取、机器检查或人工审核阶段尚未结束，而全局对比基准已经推进到新快照。

如果下一次只重新比较文件，已固定但尚未交付的产品可能显示“没有变化”，从而被错误遗忘。普通人工拒绝也不能自动表示审核人已经决定永不交付该产品。

## 决定

1. HTML 和可信配置文本使用 Git 文件比较；`soft-category.json` 文本变化后继续比较业务映射。
2. 任一语言 HTML、实际配置依赖或处理相关 Product Definition 字段变化，都处理完整双语产品。
3. Product Definition 只把双语源路径、页面类型和 Strategy 作为重新处理条件；旧 `capability_status`、显示名称、Slug 和纯展示 Category 不触发抽取。
4. 第一版同一时间只允许一个未结束增量 Batch。
5. 失败、阻断、待审核和普通拒绝都保留为未解决产品。只有完整双语 Delta Release，或真实审核人明确“结束而不交付”，才能结束对应产品。
6. 对比基准和交付状态彼此独立；推进对比基准不代表内容已经交付。

## 理由

这些规则保证变化判断使用可读输入，任一语言都不会被单独遗落；同时，Batch 固定输入让抽取、L3a、L3b 和人工审核看到同一份内容。唯一未结束 Batch 的限制使第一版状态明确，避免多个未完成快照交叉覆盖。

## 影响

- 没有业务变化时不创建空 Batch，但可以确认无害配置文本变化和 Product Definition 投影。
- 配置影响范围优先使用生产抽取记录的实际查询；缺证据的可能消费者会保守重跑。
- 新增快照可能暂时无法启动，直到当前增量 Batch 的全部产品已经交付或明确结束而不交付。
- 审核拒绝后，产品仍会出现在未解决状态中；这是一项有意的保护，不是状态遗漏。
