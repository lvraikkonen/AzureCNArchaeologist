## 2. 首个正式消费者应复用什么

v0.5.2 应以 ADR-0091 和现有最小契约为边界，为正式 Batch 中的 `api-management` 建立第一份 Independent Fidelity Evidence：

1. 引用 immutable `input-manifest.json` 中该 Batch Item 的 Source、Normalized Input、Product Definition、config、适用 route-map/soft-category 身份；
2. 引用 current `batch-manifest.json` revision 和该 item 的 persisted payload path/SHA/output record；
3. 用独立实现重建 `api-management` 的区域状态内容，不导入生产 Strategy、Reachability Resolver、Source Content Projector、Region Processor、HTML cleaner、允许转换执行或 payload builder；
4. 对每个 qualified state 保存 Source、Expected、Payload、diff、criteria/locator、retained/removed table IDs、实际 transform rule IDs 和 SHA；
5. 分别保存 L3a 与 L3b claim/verdict/coverage/bindings/evidence；
6. 生成第一份正式、逐状态、inert 的只读 `review.html`，但不写 Review Decision 或任何 `manual_l3b_*` 状态。

`20260811T171630Z-e80afabe` 是可复用的正式 execution/L3a reference 输入。v0.5.2 Execution Plan 必须在编码前明确首份 L3b Evidence 是绑定其中的一个还是两个 `api-management` 语言 item，或是否需要新的 clean single-product Batch；不能让实现隐式决定覆盖范围。无论选择哪种方式，Evidence 都必须绑定实际使用的 immutable input manifest 与 current output record，不能只引用 Planning Baseline，也不能回填 accepted v0.4.1 Batch。

## 3. 必须保留的验证性质

- `passed`、`failed`、`blocked`、`not_qualified`、`not_run` 继续按 ADR-0091 使用；执行后聚合优先级为 `failed > blocked > passed`。
- 三类 verdict-relevant 版本只有 `reconstruction_profile_version`、`wire_transform_version`、`comparison_version`。
- `applied_transform_rule_ids` 是逐状态实际应用记录；声明过的 wire transform 可通过，未声明转换必须失败。
- `evidence_semantic_identity` 不受 diff/review 排版影响；`review_projection_artifact_identity` 随可重建展示 artifact 变化。
- 受控错误必须至少再次证明 `L3a passed / L3b failed`，而不是只证明 import firewall 生效。
- review projection 始终是 Evidence 的只读投影；L4 决定仍进入现有 Review Decision 和 `inspected_states`。

## 5. v0.5.2 仍需先裁定的最小问题

在形成 Execution Plan 时只需冻结首个真实消费者必需的选择：

1. 首份正式 Evidence 的精确 Batch ID、item ID 和语言范围；
2. `api-management` 的 qualified state universe、locator 和独立 `soft-category` ownership/reconstruction 规则；
3. 哪些 wire transform rule IDs 对该 item 实际适用；
4. formal Evidence bundle 在 `runs/{batch_id}/` 下的 canonical 路径和由谁写入，但不得修改 `input-manifest.json`；
5. 如何在不改变现有 gate 的前提下并行记录 L3b，并使现有只读报告可定位该 artifact；
6. 单产品成功/失败/blocked 的退出条件与受控反证。

不要在 v0.5.2 提前冻结完整 desktop/mobile 通用模型、全局 Machine Gate activation policy、Workbench 完整交互、Release Manifest 绑定、历史回填、多用户托管或页面家族平台化。
