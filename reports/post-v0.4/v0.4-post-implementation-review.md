## 1. Executive Summary

v0.4.0 的冻结验收主张**成立**：本次 Review 独立复核了 acceptance Batch（`20260806T044456Z-e6268660`）的全部关键 artifact 哈希链、重放了 5 个真实 item 的 Source→Payload 证据链、独立重数了测试收集数（833，与 step7a 记录一致），没有发现任何能使已冻结 acceptance claim 失效的 P0/P1 证据完整性或 release gate 问题。

但 v0.4 证明的东西需要被精确理解：

1. **机器验证当前只有策略重放检查（Strategy Replay Consistency），尚无独立源内容核对。** P3 validator 的 Source 侧投影重新执行同一套策略类（`src/content_sampling/projector.py:83-111`）——这条检查有真实价值（F-01 正是它发现的平价缺陷），但它不能发现 Strategy 自身的系统性错选（"选错 DOM → 双侧一致 → PASS"），实证：zh-cn/service-bus 机器 PASS 后被人工以 CSS glyph 语义丢失拒绝。冻结文档核对结论：ADR-0087 显式收窄 v0.4 内容保证并 supersede 了 ADR-0017 的独立推导要求，当前实现**不违反**冻结承诺；独立核对是被显式延后、本轮按 execution-plan §6.4 条款重新进入计划的能力，构成 v0.5 主线（F-02）。434 项中仅 10 项经过人工审核（6 approved / 4 rejected）。
2. **发现一个真实的 validator/extractor 平价缺陷（F-01，P1-coverage）**：SupportArticle 的 extract 阶段注入了 `url_route_map`（`src/core/extraction_coordinator.py:321`），而 validator 的 Source 投影没有（`src/content_sampling/projector.py:27-34`），导致 11 个 SLA 历史版本 item 全部被机器阻断。该系统按设计 fail-closed，没有错误内容流出，但这 11 项在修复前无法进入 Review/Release。这是 v0.4.1 的首要候选。
3. **soft-category.json 是重建依据的一部分（本轮澄清修正）**：项目前提是原页面 JS 已遗失/成为黑盒，经人工考古冻结的 soft-category 是项目内部完全权威的内容归属依据，无需也不应向 live 页面或遗失 JS 求证。机器的职责是验证 Strategy **忠实执行**该依据（待 v0.5 独立源内容核对），治理的职责是把依据的 version/SHA/change-control 完整纳入 evidence chain（当前缺显式 version 与变更记录章程）（F-03）。
4. **日志与运营复杂度比预期健康**：pipeline.jsonl 很精简（1436 事件 / 431 KiB / 每 item 约 3.3 事件），真正的噪声在未持久化的 loguru 控制台输出（实测单 item 提取约 100+ 行 DEBUG/INFO）。诊断一个失败 item 需要跨 2–6 个文件；不存在单一单项说明入口。根目录 `logs/` 存在一套**休眠的** loguru 文件 sink（`setup_logging()` 全库无调用点，文件止于 2026-07-08），构成"可被无意激活的第二日志 authority"悬置风险（F-08）。
5. **主要瓶颈是 extractor/DOM 边界/state 归属（H1 强支持）**：92 个 execution failure 全部落在 DOM 边界证明、filter 结构、soft-category 投影等提取侧问题上；normalization/fidelity 侧的唯一失败簇（11 项）根因是上述平价缺陷而非 normalizer 规则本身。

**最终裁决：CLOSED WITH v0.4.1 FOLLOW-UPS。** 不满足任何重开 v0.4 的条件（详见 §3）。

## 4. Findings by Severity

### F-01 — SupportArticle validator/extractor 平价缺陷：Source 投影缺失 `url_route_map`（P1-coverage）

- **Severity**: P1（产品覆盖；非证据完整性）
- **Confidence**: High
- **Status**: Verified（本地重放复现两侧指纹）
- **Affected guarantee**: Machine Validation 对 SLA 历史版本产品族的可达性；11 个 item 被机器阻断，无法进入 Review/Release
- **Evidence**:
  - 注入点（extract 侧）：`src/core/extraction_coordinator.py:321` — `runtime_definition["extraction"]["url_route_map"] = build_support_url_route_map(definition, language)`（仅 SupportArticlePage）
  - 缺失点（validate 侧）：`src/content_sampling/projector.py:27-34` — `_runtime_definition` 只处理历史版本 slug，不注入 route map；`src/strategies/support_article_strategy.py:28` 因此拿到空 map
  - 路由表构造：`src/core/support_article_versions.py:49-67`；重写规则：`src/utils/html/url_rewriter.py:54-72`
  - 失败证据：`runs/20260806T044456Z-e6268660/validation/zh-cn/SupportArticles/SLA/sla-sql-data.content-diffs/full-content.json`（5 处 href diff）
  - 配置证据：`data/configs/products/support-articles/sla-sql-data.json`（`historical_versions[].sources.zh-cn.url → cms_path` 显式映射，如 `sql-data-v1/1.3.html → /support/sla/sql-data-v1-3/`）
  - 受影响 item（11）：`en-us/sla-sql-data{,--v1-0,--v1-4,--v1-5}`、`zh-cn/sla-sql-data{,--v1-0,--v1-3,--v1-4,--v1-5}`、`zh-cn/sla-cdn{,--v1-1}`（`reports/v0.4/full-acceptance-batch-summary.json` failure_summary）
  - 本 Review 重放：tag 代码投影 zh-cn/sla-sql-data 得 source fingerprint `ab1adb32…`，与持久化证据一致；payload 指纹 `40c934dd…` 一致；diff 精确为 5 处版本历史 href
- **分析**: payload 中的链接形态（`{base_url}/support/sla/sql-data-v1-5/`）是**配置所意图的 CMS 规范路由**，业务上反而是正确的；validator 的 Source 投影因缺少 route map 产出原始路径形态（`…/sql-data-v1_5/index.html`），于是 full-content 比较失败。即：这是 validator 与 extract 路径的**平价缺陷**，不是 payload 内容错误。系统按设计 fail-closed，11 项被阻断而非放行。
- **Why existing tests did not catch it**: Core 8 项中唯一的 support_article 是 icp-faq，其 Product Definition 没有 `historical_versions`，route map 为空，双路径天然一致；step6 determinism harness 只覆盖 Core 8 项；没有任何测试让一个带 `historical_versions` 的 SLA 产品走完 extract→validate 双路径。
- **Recommendation**: v0.4.1 在 `SourceContentProjector._runtime_definition` 对 SupportArticlePage 注入同一份 `build_support_url_route_map`（约 3 行），并新增一个"带历史版本的 SLA 产品 extract→validate 平价"回归测试。修复后需以**新 Batch** 重新裁决这 11 项（不回填、不修改冻结批次）。
- **Destination**: v0.4.1

### F-02 — 机器验证当前只具备 Strategy Replay Consistency；Independent Frozen Source Fidelity Oracle 缺失（P2，架构能力缺口）

- **Severity**: P2（架构能力缺口；术语层面已有 ADR-0087 命名纪律防护）
- **Confidence**: High
- **Status**: Verified（代码路径 + 实证案例 + 冻结文档核对）
- **Affected guarantee**: "validation passed" 的证明范围
- **Evidence**:
  - `src/content_sampling/projector.py:83-111`：Source 投影按策略名实例化 `SimpleStaticStrategy` / `RegionFilterStrategy` / `ComplexContentStrategy` / `SupportArticleStrategy` 并重跑 `extract_flexible_content` —— 与 extract 阶段同一套类、同一 DOM 选择实现
  - `src/content_sampling/runtime.py:630-660`：Source 侧与 Payload 侧经同一 `PayloadContentProjector` adapter 取值后比较指纹
  - 实证：zh-cn/service-bus 机器验证 PASS（full-content 指纹 `a32875f1…` 双侧一致），人工审核以 `extractor_defect` 拒绝（decision `4c1a1fb3…`：「表格中icon icon-tick 并没有被提取出符号」）—— 空 `<i class="icon icon-tick"></i>` 的可见符号由 CSS glyph 渲染，机器双侧一致地"丢失"，Replay lane 无法自见
  - 冻结文档核对：ADR-0017 要求 source/payload 两侧走 "independent collection and state-assignment paths"，"Validation must not reuse the production extractor's table selection, filter mapping, or fallback decisions"；但 ADR-0087 显式 supersede ADR-0013–0023（含 0017）的 v0.4 runtime scope（"Step 4 does not require PricingFact, … FactInventory, … complete Expected/Observed/Diff inventories"），并把 v0.4 verdict 收窄命名为 "Sampled State Content Consistency"；execution-plan §6.4 规定被延后的内容保证"只能在 Post-v0.4 Roadmap Re-baseline 后按真实证据重新进入计划"
- **分析（两条 Validation Lane 的边界）**:
  1. **Strategy Replay Consistency Validation（已实现，保留）** —— 当前机制。它证明：相同冻结输入与配置下重放一致；extract 与 validate 的 runtime definition 平价；payload 持久化无漂移；route map / Profile / Config 在两条路径上的不一致会报警（F-01 正是这条 lane 发现的真实缺陷）；evidence 与 payload 一致。这是有价值的回归与平价保障，应当保留。
  2. **Independent Frozen Source Fidelity Validation（缺失，v0.5 建设）** —— 产品原始意图要求的机制：Source 侧由独立 Oracle 直接从 Frozen Truth（Frozen HTML + Product Definition + soft-category Truth + route map + state/ownership contract）经 DOM selector / TabCategory / filter state / 冻结 ownership 规则定位真实 Source fragment，再按同一 state identity 与 Persisted Payload 的 `contentGroups[].content` 经**同一个 canonical normalizer** 比较。Oracle 不得调用 Extractor Strategy，不得复用 Strategy 的 DOM selection、ownership 推导或 contentGroups 组装路径；可共享的只有：Frozen HTML、Product Definition、soft-category.json、route map、state identity、ownership Truth 与 canonical normalizer。它用于发现 Strategy 自身的错选、漏选、多选、顺序错误、multiplicity 错误与 state ownership 错误。
- **修正后的结论**: 当前机器实现只具备 Strategy Replay Consistency，尚未具备独立 Frozen Source Fidelity Oracle。**机器原则上可以基于冻结 Truth 验证 Fidelity，但 Source 选择实现必须独立于 Extractor Strategy。** 这不构成 v0.4 缺陷：ADR-0087 在冻结时显式收窄了内容保证范围，当前实现与冻结 verdict（Sampled State Content Consistency）一致；Independent lane 是被显式延后、本轮按 execution-plan §6.4 条款重新进入计划的能力。
- **人工审核的保留职责**（不因 Independent Oracle 落地而消失）：Truth/ownership 是否符合业务意图；CSS/JS-dependent semantics（service-bus glyph 案对两个机器 lane 都不可见）；CMS portability；最终 approval/rejection。
- **Impact**: 在 Independent lane 缺失期间，任何系统性 extractor 选择错误（选错 DOM、漏选、ownership 错误）都会双侧一致地通过 Replay lane。434 项中仅 10 项经过人工审核；其余 266 个 machine-pass 项的内容正确性未被任何独立一方验证。ADR-0087 的 verdict 命名纪律在术语上作了防护，但 acceptance/README 层面对 "validation passed" 的通俗转述仍可能被读成内容正确性保证。
- **Why existing tests did not catch it**: 这不是 bug 而是架构能力缺口；测试体系（golden/determinism）钉的是"行为不变"，不钉"行为正确"；且 v0.4 冻结 scope（ADR-0087）并未要求该能力。
- **Recommendation**: v0.5 以独立源内容核对为基础主题（见 roadmap-rebaseline §4）：v0.5.0 先用四类真实 Frozen HTML 验证独立定位是否可行；v0.5.1 再定义重建依据和两类机器检查契约；v0.5.2–v0.5.3 实现并扩展生产能力。独立核对须以受控错误证明能发现同实现重放看不到的错选，并在 acceptance/handoff 中明确两类检查各自能证明什么。
- **Destination**: v0.5.0–v0.5.3；v0.4.1（文档术语纪律）；No action（现有策略重放机制保留不动）

### F-03 — soft-category.json 是重建依据的一部分；机器检查忠实执行，人工管理变更（P2）

- **Severity**: P2
- **Confidence**: High
- **Status**: Verified（机制与治理链现状）；Truth 内容本身按产品前提接受为权威，无需外部裁决
- **Affected guarantee**: RegionFilter/Complex state 内容归属的正确性；重建依据变化后历史证据的当前使用资格
- **产品前提（本轮澄清修正）**: 本项目的成立背景是原页面 JavaScript 已遗失或成为不可恢复的黑盒，无法依赖原始 JS 重建动态页面行为，必须从 Frozen HTML 抽取内容并交给 CMS 系统管理。因此经人工考古分析并冻结的 `soft-category.json` 不是临时推测，也不是等待 live 页面背书的辅助配置，而是项目内部完全权威的内容归属依据。完整重建依据为：**Frozen HTML + Product Definition + soft-category.json + route map + state/ownership rules + allowed transformation contract**。
- **Evidence**:
  - zh-cn/api-management Frozen Source（`data/prod-html/zh-cn/pricing/api-management.html`，SHA `2ff654ac…`）：5 个区域选项仅存在于筛选控件（desktop `hidden-sm hidden-xs` 与 mobile select 两处重复），全文唯一 `tab-panel#tabContent1` 内含 3 张表（`API-Management-preview` 4 档、`API-Management-preview2` 3 档、`API-Management-gateway`），DOM 中无区域→表关联——该关联知识属于已遗失的 JS 行为，正是 soft-category Truth 所重建的内容
  - Truth 载体：`data/configs/soft-category.json:7429-7463`（5 行人工考古配置，2026-07-26 提交 4bc2960 引入），语义为**排除表**（为某区域移除列出的表）；执行 primitive：`src/core/strict_soft_category_projection.py` 的 `remove_exact_owned_tables`（约 line 200 起，fail-closed）；运行日志实证：「需要移除的表格IDs: ['#API-Management-preview2']」（east-china2）

核心论断：**v0.4 的机器链是单 lane 的 Strategy Replay Consistency 证明系统**（可复现性 + 双路径平价 + 契约一致性），**Independent Frozen Source Fidelity lane 尚不存在**。这不违反任何冻结承诺——ADR-0087 将 v0.4 内容保证显式收窄为 "Sampled State Content Consistency"，并随其治理对象（Pricing Fact Inventory 等模型）一并 supersede 了 ADR-0017 的独立推导要求；execution-plan §6.4 规定该类能力只能在 Post-v0.4 Re-baseline 后按真实证据重新进入——本轮评审与该条款对接，产品意图已确认恢复 Independent lane，v0.5 以其为基础主题。在此之前，内容正确性的权威分布为：fail-closed ownership 机制（保证"不猜"）+ 人工审核（保证"选对"与业务意图）+ golden/determinism（保证"不变"）。任何把 "validation passed" 转述为 "内容正确" 的叙述仍是过度宣称；v0.4 文档在 ADR 层面严谨，在 README/hand-off 层面存在被误读的空间。
